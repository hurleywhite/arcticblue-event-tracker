# ArcticBlue Event Tracker Rebuild — Opportunity Pipeline

## Goal
Turn the tracker from a large event directory into an operating system for deciding where ArcticBlue should spend attention, who should own each opportunity, how travel affects the decision, and what action happens next.

## Commercial priority
1. Thor — primary commercial target; stage-oriented; healthcare / healthtech / life sciences / medtech.
2. Verma — primary commercial target; stage-oriented; insurance / banking / fintech / capital markets.
3. Jerome — primary commercial target; room-oriented; EMEA enterprise buyers. Default base: London.
4. Carlos — secondary commercial target; room-oriented; LatAm, fintech-heavy.
5. Joe / Jim / Scott / others — partner opportunities; do not compete with the main commercial queue.

Default location assumptions when no calendar travel signal exists:
- Thor: New York City
- Verma: New York City
- Jerome: London

Calendar evidence always overrides the default base.

## Product model
The system should have two layers.

### 1. Candidate universe
A large hidden pool generated by AI/search/curation. Hundreds of rows are acceptable here. Candidates are deduped, source-verified, and scored, but do not automatically become active opportunities.

### 2. Active opportunity queue
Only events with a plausible next action are promoted. Target operating range: roughly 10–20 Pursue and 20–40 Monitor items, not a hard quota.

An active opportunity must have at least one action:
- apply
- organizer outreach
- attend for buyers
- exploit an existing trip
- monitor a specific opening/deadline

## Main views
### Apply Now
Open or imminent CFP / speaker opportunity with strong persona fit.

### Reach Out
No strong public application path, but a program/content/partnership contact can plausibly unlock a slot or introduction.

### Along the Route
A commercially strong event in the same city/region as existing travel within approximately ±4 days.

### Conflicts
Strong events that overlap geographically or temporally with a different trip or another high-value event.

### Watchlist
Strong enough to retain, but no immediate action yet.

### Partner Opportunities
Joe/Jim/Scott/other partner-specific events kept separate from Thor/Verma/Jerome/Carlos commercial workflow.

## Scoring
Score each event separately for each person.

- Commercial Fit — 35%
  - regulated-industry buyer density
  - end-user executive representation
  - relevance to current ArcticBlue commercial motion
- Persona Fit — 25%
  - stage theme match for Thor/Verma
  - buyer-room fit for Jerome/Carlos
- Access / Actionability — 20%
  - open CFP
  - program director/contact
  - built-in 1:1 meetings / roundtables / meeting app
  - credible organizer route
- Logistics Fit — 15%
  - already in city
  - nearby regional trip
  - default base
  - requires new trip
  - geographic conflict
- Strategic Signal — 5%
  - target accounts speaking
  - warm connections
  - exceptional prestige / partner leverage

High priority must be rare. Generic relevance is not enough.

## Calendar geography
For every candidate and relevant owner:
1. Read calendar window covering the event plus roughly four days before/after.
2. Look first for all-day travel/location markers, flights, hotels, city labels, and event travel.
3. If a calendar location exists, use it.
4. Otherwise apply default base for Thor/Verma/Jerome.
5. Classify:
   - Already nearby
   - Nearby trip
   - Requires new trip
   - Geographic conflict
   - Unknown
6. Meeting conflicts are secondary to geography. Recurring generic Busy blocks are not automatically disqualifying.

## Travel-triggered discovery
Whenever a future calendar location is found for Thor, Verma, or Jerome:
- create/update a travel window
- search the same city first
- then nearby hubs / easy rail or short-flight cities
- search roughly ±4 days (can widen to ±14 for sparse markets)
- promote only events that still clear commercial/persona criteria

Example:
Thor calendar says Munich Sep 17–20 → search Munich/DACH Sep 13–24 for healthcare executive, enterprise AI/product transformation, innovation, and strong stage opportunities.

## Target-account / event-speaker graph
Discovery should run in both directions:

### Event-first
Find high-quality events and inspect their speaker/attendee roster.

### Account-first
Maintain a curated target-account list. Search where relevant senior leaders are speaking or attending.

High-value signals:
- target account executive is a speaker
- multiple target accounts represented
- end-user CIO/CTO/CAIO/CDO/COO/CPO/digital/innovation leaders
- warm connection path exists

Vendor CEOs should not carry the same weight as end-user buyers.

## Applications and outreach
Application/outreach pipeline becomes first-class.

Canonical stages:
- Submitted
- Initial outreach
- Followed up
- Meeting held
- Booked
- Rejected
- Attending

For every active opportunity show:
- owner
- next action
- due date
- application status
- contact status
- best contact
- last touch
- next follow-up

Do not infer a submission/outreach stage from event relevance; only set it when an action actually occurred.

## Contact strategy
For Tier A opportunities, research in this order:
1. conference/program director
2. speaker/content lead
3. relevant track chair
4. partnerships/sponsorship lead
5. past speaker or mutual/warm connection

Store verified source URLs and confidence. Avoid guessed email addresses presented as fact.

## Postmortem
An attended event is incomplete until a postmortem is entered.

Required metrics:
- speaking achieved
- senior buyer conversations
- qualified leads
- follow-up meetings
- useful partnerships
- estimated trip cost
- would attend again
- why

Use accumulated outcomes to recalibrate future event scoring. The first phase should use historical examples as few-shot evidence, not pretend the current sample is large enough for a predictive ML model.

## Automated discovery cadence
ChatGPT research runs Monday / Wednesday / Friday mornings.

Each run:
1. find newly announced/actionable candidates
2. dedupe against manual_events + deleted_events
3. verify official sources
4. score for Thor, Verma, Jerome; Carlos secondary
5. check calendar geography
6. actively search around known trips
7. prefer target-account/end-user-speaker events
8. promote only actionable, high-quality opportunities
9. preserve all human workflow fields
10. verify database writes

### Phase 2 — UI
- rebuild home around Apply Now / Reach Out / Along the Route / Conflicts / Watchlist
- person tabs with Thor, Verma, Jerome first

### Phase 3 — Graph + contacts
- target-account list

## Migration principle
All initial changes are additive. Do not delete the existing catalog or manual_events. Existing rows can be promoted into the new opportunity layer gradually. This allows side-by-side validation before switching the UI default.
